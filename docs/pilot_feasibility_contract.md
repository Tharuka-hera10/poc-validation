# Phase 0 feasibility contract

## Research question and authority

GIR-ER investigates whether source-evidence-conditioned, candidate-specific pre-commit 2/3-hop answer changes add useful information beyond an equally informed matcher. This is an unvalidated hypothesis; zero or negative incremental value must remain possible.

Read locally: updated AGENTS.md, GIR_ER_PyCharm_Codex_Plan.md and docs/research_context/FYP_Master_Research_Context.md. The master context contains summaries of review feedback, not an authenticated direct supervisor decision. Separate supervisor feedback, proposal draft, literature-review draft, critical literature review and primary papers are absent locally. The updated governing instructions supply LACE/ASPEN/ASPEN+ boundaries; their papers were not independently reviewed during this data audit. Missing literature is permitted for Phase 0, but authoritative context is required before identity-risk design.

Existing work already covers collective and constraint-aware ER, query reasoning, merge justifications and local value merging. This phase neither claims novelty for them nor implements an ASP solver. Future evidence assessment must distinguish identity equivalence, source-triple support, path composition and resulting-answer support. A valid sentence pointer resolves none of those semantic judgements by itself.

## Permitted and private information

The approved pilot starting point holds extraction fixed: original text, annotated relation triples and provenance can be shared equally across comparison methods. Source annotations are experimental inputs, not an oracle for support. Source text must be checked independently when semantic judgements are required.

True candidate identity labels, independently verified answers and controlled-fragmentation parent maps remain evaluation-only. No private-gold directory or annotation was created or read. Raw coreference indices in audit examples are preparation provenance, not ready-to-use inference features for future fragmented entities. Phase 2 must create opaque IDs and keep construction maps private; it must not copy all incident edges to every fragment.

Train/dev support descriptive feasibility inspection. Test is limited to integrity, schema, aggregate statistics/evidence coverage and overlap checks; it is absent from structural pattern and alias-collision discovery. The train/dev duplicate text must be addressed before later partition claims; nothing was silently dropped.

## Phase 0 acceptance and next gate

Acceptance: all inputs parse and validate, missing evidence is reported without truth claims, source hashes match before/after, structural counts are bounded and traceable, incomplete results fail explicitly, and automated tests cover failure cases and boundaries. The generated audit and separate feasibility report record observed execution.

Technical progression to Phase 1 is conditional on student approval, not on proving GIR-ER effectiveness. Phase 1 can build a document-scoped directed typed provenance graph from these annotations, preserving duplicates/loops and missing evidence. It must not silently collapse cross-document names. Relation codes may remain uninterpreted until authoritative metadata is available.

Scientific progression beyond preparation requires genuine independently checked identity cases, defensible fragmentation if used, source-checkable path meanings and QA references, partition policy, and an operational evidence protocol. Do not select workload templates after seeing private outcomes. B3+same-evidence remains mandatory before impact-attribution claims; later baseline, risk and sequential-merge protocols need review. No numerical success targets, thresholds or risk formula are fixed by this contract.

## Unresolved limitations

- Corpus provenance, licence, original release integrity and readable relation definitions are not established by local hashes. Hashes identify these bytes only.
- Existing JSON has within-document coreference, not a ready-made cross-document identity benchmark or independently verified multi-hop answers.
- Missing evidence pointers may require broader source review. Annotated support for individual triples does not prove a composition or resulting answer.
- Source-text duplication threatens partition independence; type inconsistencies and name/span differences need preservation and later inspection.
- Git currently tracks raw files and ignores all docs but not private gold. Configuration is unchanged as instructed. Resolve exclusions before future private annotations; no publication was performed.
- Annotation effort and availability of genuine hard negatives remain unmeasured. Structural abundance does not establish a useful research benchmark.

Phase 0 ends with STOP. No graph builder, candidates, query answers, merge simulation, operational evidence checker, risk scorer or comparison experiment is authorised here.
